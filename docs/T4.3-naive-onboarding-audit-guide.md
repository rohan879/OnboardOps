## Overview

Conduct a "naive" onboarding attempt on the demo repository fork, pretending you've never seen it before. Document every friction point with timestamps. These friction points become the foundation for auto-recovery patterns.

## Acceptance Criteria

✅ Friction document committed with at least 5 distinct friction points and timestamps

## What is a "Naive" Onboarding?

**Naive onboarding** means:
- ❌ Don't read the full README first
- ❌ Don't look for .env.example
- ❌ Don't check if Docker is running
- ❌ Don't verify Node/Python versions
- ✅ DO try to run the most obvious commands
- ✅ DO document every error you hit
- ✅ DO record timestamps for each friction point
- ✅ DO note what you had to do to fix each issue

**Why?** This simulates how a real developer onboards - they try the obvious thing, hit an error, figure it out, and move on. OnboardOps should automate this entire process.

## Common Friction Points to Watch For

### 1. Docker Not Running
- **Error:** "Cannot connect to the Docker daemon"
- **Detection:** `docker ps` exit code != 0
- **Recovery:** Start Docker Desktop, wait for ready

### 2. Missing Dependencies
- **Error:** "ModuleNotFoundError" or "Cannot find module"
- **Detection:** Import errors in stderr
- **Recovery:** Run `pip install -r requirements.txt` or `npm install`

### 3. Environment Variables
- **Error:** "KeyError" or "environment variable not set"
- **Detection:** Config errors mentioning env vars
- **Recovery:** Copy .env.example to .env, populate defaults

### 4. Port Conflicts
- **Error:** "Address already in use"
- **Detection:** Bind error with port number
- **Recovery:** Kill process on port or use alternative

### 5. Database Issues
- **Error:** "Connection refused" or "relation does not exist"
- **Detection:** Database connection errors
- **Recovery:** Start database, run migrations

### 6. Version Mismatches
- **Error:** "requires Python 3.11" or "Node version mismatch"
- **Detection:** Version check failures
- **Recovery:** Switch to correct version via pyenv/nvm

### 7. Missing Configuration Files
- **Error:** "FileNotFoundError: config.yml"
- **Detection:** File not found errors
- **Recovery:** Create from template or use defaults

### 8. Permission Issues
- **Error:** "Permission denied"
- **Detection:** EACCES or permission errors
- **Recovery:** chmod +x or run with appropriate permissions

## Audit Script Template

Use this script to conduct the audit:

```bash
#!/bin/bash
# Naive Onboarding Audit Script

AUDIT_LOG="notes/demo-repo-friction.md"
START_TIME=$(date +"%H:%M:%S")

echo "# Naive Onboarding Audit - Demo Repository" > "$AUDIT_LOG"
echo "" >> "$AUDIT_LOG"
echo "**Auditor:** Dev 4" >> "$AUDIT_LOG"
echo "**Date:** $(date +"%Y-%m-%d")" >> "$AUDIT_LOG"
echo "**Start Time:** $START_TIME" >> "$AUDIT_LOG"
echo "**Repository:** onboardops-demo (fork of tiangolo/full-stack-fastapi-template)" >> "$AUDIT_LOG"
echo "" >> "$AUDIT_LOG"
echo "---" >> "$AUDIT_LOG"
echo "" >> "$AUDIT_LOG"

# Function to log friction point
log_friction() {
    local title="$1"
    local timestamp="$2"
    local command="$3"
    local error="$4"
    
    echo "### Friction Point: $title" >> "$AUDIT_LOG"
    echo "" >> "$AUDIT_LOG"
    echo "**Timestamp:** $timestamp" >> "$AUDIT_LOG"
    echo "**Command:** \`$command\`" >> "$AUDIT_LOG"
    echo "**Error:**" >> "$AUDIT_LOG"
    echo "\`\`\`" >> "$AUDIT_LOG"
    echo "$error" >> "$AUDIT_LOG"
    echo "\`\`\`" >> "$AUDIT_LOG"
    echo "" >> "$AUDIT_LOG"
}

# Clone repository
echo "Cloning repository..."
CLONE_START=$(date +"%H:%M:%S")
git clone https://github.com/YOUR_TEAM_ORG/onboardops-demo /tmp/audit-demo 2>&1 | tee /tmp/clone-output.txt
cd /tmp/audit-demo

# Attempt 1: Try to run without setup
echo "Attempt 1: Running without setup..."
ATTEMPT1_TIME=$(date +"%H:%M:%S")
docker-compose up 2>&1 | head -20 > /tmp/attempt1-error.txt
ERROR1=$(cat /tmp/attempt1-error.txt)

if [ ! -z "$ERROR1" ]; then
    log_friction "Docker Compose Failed" "$ATTEMPT1_TIME" "docker-compose up" "$ERROR1"
fi

# Continue with more attempts...
# Document each friction point as you encounter it

echo "" >> "$AUDIT_LOG"
echo "---" >> "$AUDIT_LOG"
echo "" >> "$AUDIT_LOG"
echo "**Audit completed at:** $(date +"%H:%M:%S")" >> "$AUDIT_LOG"
echo "**Total friction points:** [COUNT]" >> "$AUDIT_LOG"
```

## Tips for a Good Audit

### DO:
✅ Start with a clean environment (no Docker running, no .env file)  
✅ Record exact timestamps for each friction point  
✅ Copy full error messages (not summaries)  
✅ Note what you had to Google or figure out  
✅ Document time spent on each fix  
✅ Be honest about frustration levels  

### DON'T:
❌ Skip documenting "obvious" issues  
❌ Fix things before documenting them  
❌ Assume anything about the setup  
❌ Read the entire README before starting  
❌ Use prior knowledge of the repository
