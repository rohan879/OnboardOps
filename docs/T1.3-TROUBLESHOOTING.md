# T1.3 Troubleshooting: /onboard Command Not Found

## Problem

When you type `/onboard` in Bob IDE, the command doesn't appear in the slash command list.

## Root Cause

Bob custom modes are **project-scoped** - they must be in the `.bob/` directory of the **repository you have open in Bob IDE**, not in a different repository.

## Solution

You need to **copy the `.bob/` directory** from the OnboardOps repository to your **demo repository**.

---

## Step-by-Step Fix

### Step 1: Identify Your Demo Repository

From Phase 1 T4.2, you should have selected and forked a demo repository. Common choices:
- `tiangolo/full-stack-fastapi-template`
- `encode/starlette`
- `tiangolo/sqlmodel`

**Find your demo repo path**:
```bash
# Check your notes
cat notes/demo-repo-choice.md

# Or check Phase 1 documentation
cat docs/PHASE1-DEV4-PROGRESS.md
```

### Step 2: Copy .bob/ Directory to Demo Repo

**Option A: Manual Copy (Recommended)**

```bash
# Navigate to your demo repo
cd /path/to/your/demo-repo

# Copy the entire .bob/ directory from OnboardOps
cp -r c:/Projects/Hackathon/IBM/OnboardOps/.bob/ .

# Verify it copied
ls -la .bob/
# Should show: modes/, skills/, rules/, commands/, mcp.json
```

**Option B: Symlink (Advanced)**

```bash
# Navigate to your demo repo
cd /path/to/your/demo-repo

# Create symlink to OnboardOps .bob/
ln -s c:/Projects/Hackathon/IBM/OnboardOps/.bob/ .bob

# Verify
ls -la .bob/
```

### Step 3: Verify Files Exist in Demo Repo

```bash
# In your demo repo, check these files exist:
ls -la .bob/modes/onboard.md
ls -la .bob/skills/repo-cartography.md
ls -la .bob/skills/certification.md
ls -la .bob/rules/cartography-style.md
ls -la .bob/mcp.json
```

All should exist and not be empty.

### Step 4: Restart Bob IDE

1. **Close Bob IDE completely** (not just the window, quit the application)
2. **Reopen Bob IDE**
3. **Open your demo repository** (not OnboardOps)
4. Wait 5-10 seconds for Bob to load the workspace

### Step 5: Verify Mode Loaded

**Method 1: Check Slash Commands**
1. Click in Bob's chat panel
2. Type `/`
3. Look for `/onboard` in the dropdown list

**Method 2: Check Bob Settings**
1. Open Bob Settings (Cmd/Ctrl + ,)
2. Go to "Modes" section
3. Look for "OnboardOps Onboard Mode" in the list

**Method 3: Check Bob's Context**
1. In Bob chat, type: "What custom modes are available?"
2. Bob should mention the onboard mode

### Step 6: Test the Command

```
/onboard
```

**Expected Response** (within 5 seconds):
```
Welcome to [your-demo-repo-name]! I'm your onboarding guide.

🕐 Stopwatch started.

What's your name and preferred pronoun?

Let's begin by mapping this codebase's architecture. I'll walk you through 
the dependency structure, entry points, change hotspots, and conventions—
then we'll get your environment running and ship your first PR.
```

## Common Issues

### Issue 1: "Mode file has syntax errors"

**Symptom**: Bob shows error when loading mode

**Fix**:
```bash
# Validate YAML front matter
cd c:/Projects/Hackathon/IBM/OnboardOps
head -20 .bob/modes/onboard.md

# Should show valid YAML between --- markers
# Check for:
# - Matching quotes
# - Proper indentation (2 spaces)
# - No tabs
```

### Issue 2: "MCP server not found"

**Symptom**: Mode loads but MCP tools fail

**Fix**:
```bash
# Verify MCP server running
curl http://127.0.0.1:8765/health

# If not running, start it:
cd c:/Projects/Hackathon/IBM/OnboardOps
./scripts/start-integration-test.sh

# Verify .bob/mcp.json exists in demo repo
cat .bob/mcp.json
```

### Issue 3: "Skills not found"

**Symptom**: Mode loads but cartography doesn't run

**Fix**:
```bash
# Verify skills exist in demo repo
ls -la .bob/skills/repo-cartography.md
ls -la .bob/skills/certification.md

# If missing, copy from OnboardOps:
cp c:/Projects/Hackathon/IBM/OnboardOps/.bob/skills/*.md .bob/skills/
```

### Issue 4: Bob IDE doesn't recognize .bob/ directory

**Symptom**: No custom modes appear at all

**Possible Causes**:
1. **Wrong directory open**: Make sure demo repo is open, not OnboardOps
2. **Bob version too old**: Update Bob IDE to latest version
3. **Workspace not initialized**: Close and reopen Bob IDE
4. **Permissions issue**: Check .bob/ directory is readable

**Fix**:
```bash
# Check Bob version
# In Bob IDE: Help → About

# Check directory permissions
ls -la .bob/
# Should show readable files (not 000 permissions)

# Force reload workspace
# In Bob IDE: File → Reload Window
```

## Quick Diagnostic Script

Run this in your demo repo to check everything:

```bash
#!/bin/bash
# Save as: check-onboard-setup.sh

echo "=== OnboardOps Setup Diagnostic ==="
echo ""

echo "1. Checking .bob/ directory..."
if [ -d ".bob" ]; then
    echo "   ✓ .bob/ exists"
else
    echo "   ✗ .bob/ NOT FOUND"
    echo "   → Copy from OnboardOps: cp -r /path/to/OnboardOps/.bob/ ."
    exit 1
fi

echo ""
echo "2. Checking mode file..."
if [ -f ".bob/modes/onboard.md" ]; then
    echo "   ✓ onboard.md exists"
    lines=$(wc -l < .bob/modes/onboard.md)
    echo "   → $lines lines"
else
    echo "   ✗ onboard.md NOT FOUND"
    exit 1
fi

echo ""
echo "3. Checking skills..."
if [ -f ".bob/skills/repo-cartography.md" ]; then
    echo "   ✓ repo-cartography.md exists"
else
    echo "   ✗ repo-cartography.md NOT FOUND"
fi

if [ -f ".bob/skills/certification.md" ]; then
    echo "   ✓ certification.md exists"
else
    echo "   ✗ certification.md NOT FOUND"
fi

echo ""
echo "4. Checking MCP config..."
if [ -f ".bob/mcp.json" ]; then
    echo "   ✓ mcp.json exists"
else
    echo "   ✗ mcp.json NOT FOUND"
fi

echo ""
echo "5. Checking backend..."
if curl -s http://127.0.0.1:8765/health > /dev/null 2>&1; then
    echo "   ✓ Backend running on port 8765"
else
    echo "   ✗ Backend NOT running"
    echo "   → Start: ./scripts/start-integration-test.sh"
fi

echo ""
echo "6. Checking frontend..."
if curl -s http://localhost:3000 > /dev/null 2>&1; then
    echo "   ✓ Frontend running on port 3000"
else
    echo "   ✗ Frontend NOT running"
    echo "   → Start: cd frontend && pnpm dev"
fi

echo ""
echo "=== Setup Status ==="
echo "If all checks pass, try /onboard in Bob IDE"
echo "If any fail, follow the fix instructions above"
```

**Usage**:
```bash
cd /path/to/your/demo-repo
bash check-onboard-setup.sh
```
