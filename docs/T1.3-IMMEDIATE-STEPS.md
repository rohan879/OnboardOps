# T1.3 Immediate Troubleshooting Steps

**Current issue**: `/onboard` does not appear in Bob IDE command results.

## Step 1: Verify Workspace Location

You must have the demo repository open in Bob IDE, not the OnboardOps implementation repository.

1. Check the Bob IDE window title.
2. It should show the selected demo repo name.
3. If it shows `OnboardOps`, close that window and open the demo repository instead.

Example:

```powershell
code C:\Projects\Hackathon\IBM\demo-repo
```

## Step 2: Fully Quit Bob IDE

1. Close Bob IDE completely, not just the active workspace window.
2. Wait 10 seconds.
3. Reopen Bob IDE.
4. Open the demo repository again.

## Step 3: Verify Mode Files

The demo repository should contain the current `.bob/` directory from OnboardOps.

Required files:

- `.bob/custom_modes.yaml`
- `.bob/commands/onboard.md`
- `.bob/modes/onboard.md`
- `.bob/skills/repo-cartography.md`
- `.bob/skills/certification.md`
- `.bob/rules/cartography-style.md`
- `.bob/mcp.json`

The mode front matter should start like this:

```yaml
---
name: OnboardOps Onboard Mode
slug: onboard
description: Socratic mentor for new engineering hires
skills:
  - repo-cartography
  - certification
mcp_servers:
  - institutional-knowledge
---
```

## Step 4: Check Bob IDE Mode Settings

1. Open Bob IDE Settings.
2. Search for custom modes or project modes.
3. Confirm that `OnboardOps Onboard Mode` appears.
4. Confirm that project-scoped modes are enabled if Bob exposes that setting.

## Step 5: Test A Minimal Mode

Create `.bob/modes/test.md` in the demo repository:

```markdown
---
name: Test Mode
slug: test
description: Simple test
---

# Test Mode

Say "Test mode working!" when invoked.
```

Reload Bob and type `/test`.

- If `/test` works, the issue is specific to the onboard mode.
- If `/test` does not work, the Bob IDE build may not be loading project custom modes.

## Step 6: Manual Invocation Fallback

If custom modes do not load, T1.3 can still validate the cartography flow. Paste this into Bob chat:

```text
I want you to act as the OnboardOps Onboard Mode.

You are a Socratic mentor for new engineering hires joining an unfamiliar codebase.
Guide me through structured discovery, not direct code-writing.

Start with a four-part greeting:
1. One-line greeting mentioning this repository by name
2. Stopwatch signal: "Stopwatch started."
3. Ask for my name and preferred pronoun
4. First cartography prompt about mapping the codebase

Then proceed with the repo-cartography skill:
- Stage 1: dependency graph with real data
- Stage 2: entry points placeholder
- Stage 3: hotspots placeholder
- Stage 4: conventions placeholder

Keep the greeting under 120 words. Ask one Socratic question after the graph card.
Begin now.
```

This fallback validates the flow, but the gate should still record that slash-command discovery needs Bob IDE follow-up.

## Expected Behavior

1. Type `/` in Bob chat.
2. See `/onboard` in the command dropdown.
3. Select or type `/onboard`.
4. Bob responds within 5 seconds with the four-part greeting.
5. The dashboard receives the Stage 1 dependency graph card.
