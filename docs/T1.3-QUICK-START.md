## 🎯 What You're Testing

The **first end-to-end vertical slice** of OnboardOps:
1. Type `/onboard` in Bob IDE
2. Bob greets you and starts cartography
3. Bob builds a dependency graph from the demo repo
4. Bob emits a card to the dashboard
5. Bob asks you a Socratic question
6. Bob evaluates your answer
7. Bob runs through stub stages 2-4
8. Dashboard shows all 4 cards in real-time

## 🚀 Step-by-Step Execution

### Step 1: Start the Services (5 minutes)

**Option A: Automated (Recommended)**
```bash
# From repository root
chmod +x scripts/start-integration-test.sh
./scripts/start-integration-test.sh
```

**Option B: Manual**
```bash
# Terminal 1: Backend
cd backend
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn app:app --port 8765 --reload

# Terminal 2: Frontend
cd frontend
pnpm install
pnpm dev

# Terminal 3: Verify
curl http://127.0.0.1:8765/health
# Should return: {"status":"ok"}
```

**Expected Result**:
- ✅ Backend running on http://127.0.0.1:8765
- ✅ Frontend running on http://localhost:3000
- ✅ Health check returns 200

4. Click "Open"

### Step 3: Execute `/onboard` Command (30 minutes)

#### 3.1: Type the Command

In Bob's chat panel, type:
```
/onboard
```

Press Enter.

**Expected Response (within 5 seconds)**:
```
Welcome to [repo-name]! I'm your onboarding guide.

🕐 Stopwatch started.

What's your name and preferred pronoun?

Let's begin by mapping this codebase's architecture.
```

**✅ Checkpoint**: If you see this greeting, the onboard mode is working!

---

#### 3.2: Provide Your Name

Type:
```
Alex (they/them)
```

**Expected Response**:
Bob acknowledges and begins Stage 1 cartography.

---

#### 3.3: Watch Stage 1 Execute (60-90 seconds)

Bob will:
1. **Discover Python files** (10-20 seconds, no narration)
2. **Parse imports** (10-20 seconds, no narration)
3. **Build dependency graph** (5-10 seconds)
4. **Emit card to dashboard** (immediate)
5. **Narrate in chat** (1 sentence)
6. **Ask Socratic question** (immediate)

**Expected Dashboard Update**:
- ✅ Dependency Graph card appears
- ✅ Card shows ≥5 nodes, ≥5 edges
- ✅ Node labels visible (module names)

**Expected Chat Narration**:
```
The dependency graph reveals [module-name] as the architectural hub, imported by [N] other modules.
```

**Expected Question**:
```
Which module has the highest fan-in (is imported by the most other modules)?
```

**✅ Checkpoint**: If you see the graph card on the dashboard and the question in chat, Stage 1 is working!

---

#### 3.4: Answer the Question

**Test Case 1: Correct Answer**

Look at the dependency graph card on the dashboard. Find the module with the highest fan-in value. Type that module name:
```
[module-name]
```

**Expected Response**:
```
Correct! [module-name] is the architectural hub with [N] incoming dependencies.
```

Bob advances to Stage 2.

**Test Case 2: Incorrect Answer (Optional)**

If you want to test remediation, type a wrong module name:
```
utils.py
```

**Expected Response (First Attempt)**:
```
Let's look at the dependency graph together. The fan-in column shows how many modules import each module. [Correct module] has [N] incoming connections, making it the most imported module. Which module has the highest fan-in value?
```

Bob re-asks the question.

**Expected Response (Second Attempt)**:
```
The answer is [module-name]. It has [N] incoming dependencies: [list]. This makes it a central hub—changes here affect many other modules. Let's move to entry points.
```

Bob reveals the answer and advances to Stage 2.

---

## 🐛 Troubleshooting

### Problem: Backend won't start

**Symptom**: `uvicorn` command fails or port 8765 already in use

**Solution**:
```bash
# Check if port is in use
lsof -i :8765  # Mac/Linux
netstat -ano | findstr :8765  # Windows

# Kill process if needed
kill -9 [PID]  # Mac/Linux
taskkill /PID [PID] /F  # Windows

# Restart backend
cd backend
source .venv/bin/activate
uvicorn app:app --port 8765 --reload
```

---

### Problem: Frontend won't start

**Symptom**: `pnpm dev` fails or port 3000 already in use

**Solution**:
```bash
# Check if port is in use
lsof -i :3000  # Mac/Linux
netstat -ano | findstr :3000  # Windows

# Kill process if needed
kill -9 [PID]  # Mac/Linux
taskkill /PID [PID] /F  # Windows

# Restart frontend
cd frontend
pnpm install
pnpm dev
```

---

### Problem: Bob doesn't recognize `/onboard`

**Symptom**: Bob says "Unknown command"

**Solution**:
1. Verify `.bob/modes/onboard.md` exists in the demo repo
2. Close and reopen the demo repo in Bob IDE
3. Check Bob's mode list: Settings → Modes
4. If still not working, check Bob IDE logs

---

### Problem: Dashboard doesn't update

**Symptom**: Cards don't appear on dashboard

**Solution**:
1. Check WebSocket connection indicator on dashboard
2. Open browser console (F12) and check for errors
3. Verify backend WebSocket endpoint: `ws://127.0.0.1:8765/events`
4. Check backend logs for `emit_event` tool calls
5. Restart both backend and frontend

---

### Problem: Bobcoin spend >3

**Symptom**: Stage 1 consumes >3 Bobcoins

**Solution**:
1. This is expected for first run (no optimizations yet)
2. Record actual spend in `docs/bobcoin-tracking-t1.3.md`
3. Proceed to T1.4 for optimization
4. Target after T1.4: ≤2 Bobcoins
