# Bob IDE Setup for /onboard Command

## Issue: /onboard Not Appearing

You're in the OnboardOps repository where `.bob/modes/onboard.md` exists, but `/onboard` doesn't appear when you type `/` in Bob IDE.

## Possible Causes & Fixes

### 1. Bob IDE Hasn't Loaded the Mode Yet

**Try this first**:

1. **Reload the workspace**:
   - In Bob IDE: `Cmd/Ctrl + Shift + P`
   - Type: "Reload Window"
   - Press Enter

2. **Wait 10 seconds** for Bob to scan the `.bob/` directory

3. **Try `/` again** in the chat panel

---

### 2. Check Bob's Mode Settings

**Verify mode is registered**:

1. Open Bob Settings: `Cmd/Ctrl + ,`
2. Search for "modes"
3. Look for "Custom Modes" or "Project Modes" section
4. Check if "OnboardOps Onboard Mode" appears

**If not listed**:
- Bob may not support project-scoped modes in your version
- Check Bob version: Help → About
- Update to latest Bob IDE if needed

---

### 3. YAML Front Matter Issue

The mode file has YAML front matter. Let's verify it's valid:

**Current front matter**:
```yaml
---
name: "OnboardOps Onboard Mode"
slug: onboard
description: "Socratic mentor for new engineering hires - guides repository exploration without writing code"
skills:
  - repo-cartography
  - certification
mcp_servers:
  - institutional-knowledge
max_tokens: 8000
---
```

**Potential issues**:
- Quotes in `name` and `description` might cause parsing errors
- `max_tokens` might not be a valid field

**Try this simplified version**:

```yaml
---
name: OnboardOps Onboard Mode
slug: onboard
description: Socratic mentor for new engineering hires
skills:
  - repo-cartography
  - certification
mcp_servers:
  - institutional-knowledge
```

### 4. Bob IDE Version Compatibility

**Check if your Bob IDE supports custom modes**:

According to the SRS and Phase 1 docs, the hackathon uses "a version supporting custom modes from files, project-scoped MCP servers, Bob Shell non-interactive sessions, and checkpoints."

**If your Bob IDE is older**:
- Custom modes might not be supported yet
- You may need to use Bob's built-in modes instead
- Check Bob documentation for your version

## Workaround: Manual Invocation

If `/onboard` doesn't work, you can manually invoke the mode behavior:

**In Bob chat, paste this**:
```
I want you to act as the OnboardOps Onboard Mode.

You are a Socratic mentor for new engineering hires joining an unfamiliar codebase. 
Your mission is to guide them to their first shipped contribution in under 10 minutes 
through structured discovery, not direct instruction.

Start by giving me the four-part greeting:
1. One-line greeting mentioning this repository by name
2. Stopwatch signal: "🕐 Stopwatch started."
3. Ask for my name and preferred pronoun
4. First cartography prompt about mapping the codebase

Then proceed with the repo-cartography skill to analyze:
- Dependency graph
- Entry points  
- Change hotspots
- Project conventions

Keep responses concise (≤120 words for greeting). Be Socratic - guide with questions, 
don't write code unless explicitly in the Starter PR step.

Ready? Begin with the greeting.
```

This manually loads the mode's instructions into Bob's context.
