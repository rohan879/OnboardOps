## Overview

Created comprehensive preflight checklist script that verifies 15+ invariants before recording demo sessions. The script ensures the demo machine is in a known-good state and identifies issues that could cause recording failures.

## Implementation

### Script Location
- **File:** `scripts/preflight.sh`
- **Permissions:** Executable (`chmod +x`)
- **Execution Time:** <1 second (target: <30s)

### Check Categories

#### 1. **Dependencies** (1 check)
- Verifies required commands: `git`, `node`, `npm`, `python3`, `docker`, `curl`, `jq`

#### 2. **Git Status** (2 checks)
- Repository commit hash
- Working tree clean status

#### 3. **Authentication** (1 check)
- Bob CLI installation and authentication

#### 4. **Network** (1 check)
- Internet connectivity via google.com ping

#### 5. **System Resources** (1 check)
- Disk space availability (>10GB required)

#### 6. **Docker** (1 check)
- Docker daemon status

#### 7. **Python Environment** (1 check)
- Virtualenv presence (warning only)

#### 8. **Node.js** (1 check)
- Node.js version verification

#### 9. **Backend Health** (7 checks)
- `/healthz` - Overall health
- `/healthz/db` - Database connectivity
- `/healthz/cache` - Redis cache
- `/healthz/mcp` - MCP server
- `/healthz/ws` - WebSocket relay

#### 10. **Frontend Health** (1 check)
- Port 3000 HTTP response

#### 11. **WebSocket Server** (1 check)
- Port 8765 listener status

#### 12. **Port Availability** (3 checks)
- Port 3000 (frontend)

#### 13. **Reset Status** (1 check)
- Demo machine reset marker file

#### 14. **Bobcoin Budget** (1 check)
- Remaining Bobcoin headroom

- **Blue:** Informational messages
- **Green:** Passed checks

- `0` - All checks passed
- `1` - One or more checks failed

## Usage

### Basic Usage
```bash

```

```bash

./scripts/preflight.sh

# 2. Fix any failures

# 3. Verify all checks pass
```

## Lessons Learned

### 1. **Fast Feedback is Critical**
- Sub-second execution enables frequent checks
- Developers will actually use fast tools
- Slow checks get skipped

### 2. **Clear Output Matters**
- Color coding improves scannability
- Summary section provides quick overview
- Failed checks listed for easy action

### 3. **Warnings vs Errors**
- Some conditions are warnings (e.g., missing virtualenv)
- Bootstrap will create missing resources
- Only block on truly blocking issues

### 4. **Comprehensive Coverage**
- 23 checks cover all failure modes
- Backend health endpoints provide deep visibility
- Port checks catch service conflicts
