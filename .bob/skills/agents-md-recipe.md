# AGENTS.md Recipe Skill

This skill composes a personalized `AGENTS.md` file for the target repository, incorporating cartography Stage 1 data (dependency graph) and providing a foundation for AI agents working on the codebase.

## Purpose

The generated `AGENTS.md` serves as:
1. **Context for AI agents** - Provides repository overview and architecture
2. **Onboarding artifact** - Captures key insights from cartography
3. **Living documentation** - Updated as repository evolves

## Input Requirements

You will receive:
- **Repository path**: Absolute path to the target repository
- **Repository name**: Name of the repository (from directory or git remote)
- **Stage 1 data**: Dependency graph from cartography (JSON or text format)
- **Entry points** (optional): List of main entry points if available

## Output Format

Generate a complete `AGENTS.md` file with the following structure:

```markdown
# [Repository Name]

[One-line repository summary - infer from README, package.json, or directory structure]

## Architecture Overview

### Dependency Graph (Stage 1 Cartography)

[Insert dependency graph here - as ASCII art, markdown table, or mermaid diagram]

**Key modules:**
- [List 3-5 core modules with brief descriptions]

**Module relationships:**
- [Describe 2-3 key dependencies or patterns]

## Entry Points

[If available, list main entry points]
- CLI: [file and function]
- HTTP: [main routes file]
- Scheduled: [cron jobs or background tasks]

## Open Questions

The following questions remain for deeper exploration:

1. What are the main data models and their relationships?
2. How is error handling implemented across the codebase?
3. What testing patterns are used?
4. Are there any known technical debt areas?
5. What deployment or build processes exist?

## Next Steps for AI Agents

When working on this repository:
1. Review the dependency graph to understand module boundaries
2. Check entry points before adding new routes or commands
3. Follow existing patterns discovered in Stage 4 (conventions)
4. Consult change hotspots (Stage 3) for frequently modified areas

---

*Generated by OnboardOps cartography on [current date]*
*This file should be updated as the repository evolves*
```

## Composition Guidelines

1. **Be concise**: One-line summary should be ≤20 words
2. **Be specific**: Use actual file names and module names from the repo
3. **Be helpful**: Focus on information that helps AI agents navigate the code
4. **Be honest**: If data is missing, say so in Open Questions

## Token Discipline

- Target: ≤500 tokens for the entire AGENTS.md
- If Stage 1 data is large, summarize the top 5-10 modules only
- Prioritize clarity over completeness

## Example Output

For a FastAPI repository:

```markdown
# demo-api

A FastAPI-based REST API for user management with PostgreSQL backend.

## Architecture Overview

### Dependency Graph (Stage 1 Cartography)

```
app/main.py
  ├── app/routers/users.py
  ├── app/routers/auth.py
  ├── app/database.py
  └── app/models.py

app/routers/users.py
  ├── app/database.py
  └── app/models.py

app/routers/auth.py
  ├── app/database.py
  └── app/models.py
```

**Key modules:**
- `app/main.py` - FastAPI application entry point
- `app/database.py` - SQLAlchemy database connection
- `app/models.py` - Pydantic and SQLAlchemy models
- `app/routers/` - API route handlers

**Module relationships:**
- All routers depend on database.py for DB access
- Models are shared across routers
- Main.py orchestrates router registration

## Entry Points

- HTTP: `app/main.py` (FastAPI app)
- CLI: None detected

## Open Questions

1. What are the main data models and their relationships?
2. How is authentication implemented?
3. What testing patterns are used?
4. Are there any known technical debt areas?
5. What deployment or build processes exist?

---

*Generated by OnboardOps cartography on 2026-05-15*
```
